# OMAR MARO — Graphic Designer Portfolio

الموقع الشخصي: https://oa1963507-commits.github.io/omar-maro-portfolio/

## التشغيل والمزامنة — بدون اشتراكات مدفوعة

- استضافة مجانية عبر GitHub Pages.
- عرض كامل للصور والنصوص والفيديوهات المدعومة، بالنسب الأصلية وبدون تحسين وهمي للـDPI.
- مصدر بيانات التفاصيل: Scrappa (خدمة مستقلة غير تابعة لـAdobe)، باستخدام `SCRAPPA_API_KEY` محفوظ في GitHub Actions Secrets. الحساب المجاني يُعلن عن 500 رصيد شهريًا بدون بطاقة بنكية؛ راجع الحدود الحالية مع مزود الخدمة.
- تحديث مرة يوميًا عن طريق GitHub Actions لتقليل استهلاك الرصيد، ثم نشر تلقائي عند اكتمال المزامنة.
- ليس هناك أي اعتماد نشط على Apify أو أي اشتراك مدفوع.

## لماذا ظهرت 12 فقط رغم وجود 28 مشروعًا؟

استجابة البروفايل العامة من Scrappa أرجعت 12 رابطًا فقط، ولا يوفّر ذلك الـendpoint خيار صفحات إضافية موثقًا. قائمة التفاصيل التي يستوردها الموقع لا يمكن أن تتضمن مشروعًا غير معروف الرابط.

لإضافة باقي الروابط **مجانًا مرة واحدة**، ضعها في `data/known-projects.json`، مثل:

```json
[
  "https://www.behance.net/gallery/123456789/Project-A",
  "https://www.behance.net/gallery/123456790/Project-B"
]
```

هذه الروابط أمثلة توضيحية، وليست أعمالًا حقيقية. لا تضف أسماء أو روابط مفترضة. الكود يتحقق من أن الروابط تنتمي إلى `www.behance.net/gallery/ID/`، ويتجاهل التكرارات عند دمجها مع الـ12 الموجودة. ثم يستخدم مفتاح Scrappa الحالي لتحميل تفاصيل المشاريع التي اكتُشفت حديثًا، دون مفتاح ثانٍ.

يمكن لمالك الحساب أيضًا إرسال **قائمة الروابط العامة فقط** في المحادثة لتحديث الملف له من خلال GitHub المتصل. لا ترسل كلمات مرور أو رموز جلسة أو ملفات خاصة. إذا صدّرت صفحة Behance كاملة، يفضّل فتحها بدون تسجيل دخول، ومراجعة الملف قبل مشاركته لتجنب تضمين بيانات حساب شخصية أو رموز جلسة.

## نطاق التحديثات

- يُكتشف الجديد تلقائيًا فقط ضمن قائمة البروفايل التي يعيدها المصدر العام. المشاريع غير الموجودة في هذه القائمة تحتاج إضافة رابطها إلى `known-projects.json` حتى تُكتشف.
- المشروع لا يُعتبر مستوردًا كاملًا ما لم تُرجع خدمة التفاصيل وحدات محتواه. يتم حفظ حالات الفشل في `data/sync-status.json`.
- قد لا تسمح خدمة Scrappa بجلب تفاصيل بعض المشاريع، كما حدث سابقًا مع `dr/ahmed zakaria` و`dr/sara`. يمكن استيراد ملفات المشروع الأصلية حينها.
- لا يتطلب النظام دخولًا إلى Behance، ولا يمكنه تحرير المشاريع الموجودة هناك.
- حتى بعد إضافة 28 رابطًا، لا نعتبر المحتوى مكتملًا قبل التحقق من عدد وحدات كل مشروع ومطابقتها مع Behance.

## ملفات المشروع

- `app.js`, `styles.css`, `index.html`: واجهة الموقع.
- `data/projects.json`: القائمة المعروضة على الموقع.
- `data/known-projects.json`: روابط المشاريع العامة التي لم يرجعها مصدر البروفايل.
- `scripts/sync-via-provider.mjs`: جلب التفاصيل ودمجها.
- `.github/workflows/sync-projects.yml`: جدولة المزامنة اليومية.
- `.github/workflows/deploy-pages.yml`: النشر على GitHub Pages.

## استخراج الصور الداخلية للمشاريع من متصفح المالك (مجاني)

لأن GitHub Actions استقبل ردود HTTP 403 من Behance ولأن خدمة JSON الخارجية أرجعت محتوى بعض المشاريع ناقصًا، أُضيفت أداة تستخرج **روابط صور الوحدات العامة** من متصفح المالك نفسه، دون تخزين أو قراءة كلمة المرور:

1. افتح `tools/collect-full.html` على GitHub Pages، واسحب أداة المفضلة لشريط المفضلة في Chrome.
2. افتح `https://www.behance.net/oa19635079ead` واضغط الأداة من شريط المفضلة.
3. بعد الفحص نزّل `omar-maro-behance-full-projects.json` وارفع الملف إلى محادثة ChatGPT لمراجعة المحتوى.
4. يتم دمجه بعد التحقق من الهوية وروابط CDN باستخدام:
```bash
node scripts/import-browser-export.mjs path/to/omar-maro-behance-full-projects.json
node --test tests/import-browser-export.test.mjs
```

هذا **استيراد يدوي جماعي** للروابط والصور العامة، وليس API تدير حساب Behance أو مزامنة آلية دائمة. قد تفشل صفحات تمنع الإطارات أو ملفات الصور التي لا تُحمّل في المتصفح. لا تُوصف المشاريع بأنها كاملة إلا بعد مراجعة الصور المستوردة مقابل محتوى Behance. المستورد لا يحذف صورًا قديمة إذا كانت النتيجة الجديدة أقصر، ولا يستبدل نصوص/فيديوهات معروفة بوسائط أقل. المزامنة اليومية تتبع حدود الرصيد المجاني وتؤجل إعادة المحاولة للمشاريع غير المتاحة.

## إدارة المشاريع مباشرة من الموقع

لوحة الإدارة: https://oa1963507-commits.github.io/omar-maro-portfolio/tools/manage-projects.html

- رابط **إدارة المشاريع** موجود في الفوتر، ويمكن الوصول له مباشرة من الرابط أعلاه.
- تحمي GitHub صلاحية الكتابة الفعلية. أنشئ **Fine-grained personal access token** من GitHub، مقيدًا بمستودع `omar-maro-portfolio` فقط، بصلاحية **Contents: Read and write**. توضع قيمته في نموذج الإدارة داخل المتصفح، **ولا تُنسخ في هذه المحادثة**. المفتاح في ذاكرة الصفحة فقط، ولا يُحفظ في localStorage أو ملفات الموقع.
- من اللوحة: ترتيب بالسحب والأسهم، إخفاء وإظهار، تعديل العنوان والتصنيف والغلاف والوصف، حذف من عرض الموقع أو استعادة مشروع، إضافة أعمال بصورها/روابطها، ورفع الصور من جهازك (GitHub Contents API، حتى 8 ميجابايت للصورة).
- يتم حفظ جميع إعدادات العرض في `data/site-controls.json` منفصلة عن `data/projects.json`. ملفات Behance والـ183 صورة محفوظة. الحذف من الموقع لا يحذف مشروع Behance ويمنع رجوعه تلقائيًا في تحديثات المعرض؛ يمكن استعادته.
- بعد **نشر التعديلات** يرسل المتصفح التعديل مباشرة إلى GitHub Contents API مع `sha` للتأكد من عدم الكتابة فوق تغييرات متزامنة. يؤدي commit إلى نشر GitHub Pages تلقائيًا. لا توجد خدمات مدفوعة أو تطبيق backend إضافي.
- لأن الموقع ثابت، لا يمكن إخفاء HTML لوحة الإدارة عن الزوار؛ لكن لا يمكنهم حفظ التعديلات دون مفتاح بمستوى صلاحيات مناسب. يفضّل اختيار صلاحيات قليلة وتاريخ انتهاء للمفتاح، وعدم استخدامه على جهاز مشترك.
- لا يمكن استيراد جميع صور Behance من مجرد لصق رابط مشروع جديد في نموذج المشروع اليدوي؛ أضف صور المشروع بروابط HTTPS أو اخترها من جهازك. المزامنة المجدولة تظل مسؤولة عن محاولة اكتشاف مشاريع Behance العامة الجديدة.
