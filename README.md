# OMAR MARO — Graphic Designer Portfolio

موقع شخصي داكن (عربي + إنجليزي) مبني باللوجو والصور الأصلية المقدمة من صاحب الموقع.

## المحتويات

- واجهة مخصصة متجاوبة على الموبايل والكمبيوتر، مع دعم تقليل الحركة وإعدادات الوصول.
- معرض أعمال بفلترة حسب القسم، وصفحة مفصلة مستقلة لكل مشروع (Case Study).
- لمشاريع Behance المستوردة: صفحة خاصة مع صورة الغلاف والوصف و**تضمين المشروع الأصلي** داخلها؛ في حال عدم ظهور التضمين، رابط فتحه على Behance.
- مشروع الهوية الشخصية الأصلي والصور الأصلية؛ بدون اختلاق مشاريع أو استخدام صور أشخاص آخرين.
- نموذج طلب مشروع يفتح واتساب برسالة مُجهزة على رقم `+20 1128791108`، دون تخزين بيانات.
- مستورد تجريبي للمشاريع **العامة فقط** من Behance، مع جدولة فحص كل ست ساعات على GitHub Actions.

## Behance auto-sync: حدود ووظائف فعلية

المصدر هو **الحساب العام**: https://www.behance.net/oa19635079ead

1. يعمل GitHub Actions كل 6 ساعات تقريبًا ويجرب مصدر RSS القديم من Behance، ثم RSSHub العام.
2. بإمكانك لاحقًا ضبط متغير مستودع `BEHANCE_FEED_URL` على مصدر HTTPS موثوق يصل لهذا الحساب (RSS/Atom/JSON).
3. يفحص البرنامج أن كل مشروع يعود إلى رابط `behance.net/gallery/PROJECT_ID`؛ يستخرج العنوان والغطاء والوصف والتاريخ عندما تتوافر في المصدر.
4. يتم حفظ النتائج في `data/projects.json`. التحديث لا يمس مشاريعك اليدوية ولا يحذف مشاريع قديمة عند فشل التغذية أو عند عرض جزء منها.
5. إن فشل الوصول إلى جميع المصادر، يسجل الفشل في سجل GitHub Actions، **ولا يحدث أي تعديل** على البيانات الحالية.

**تحذير مهم:** لا توجد مفاتيح API عامة جديدة لـBehance. مصدر RSS القديم قد لا يعمل، وقد يتوقف RSSHub أو يتطلب استضافة مستقلة. نجحت الاختبارات المحلية باستخدام بيانات محاكاة، لكن **لم ينجح تحقق حي من مصدر بيانات حسابك** في بيئة التنفيذ الحالية. لذا النظام جاهز تقنيًا للتجربة، **وليس مزامنة مفعّلة أو مضمونة** حتى ينجح تشغيل على GitHub مع مشاريع فعلية.  صور المشروع كلها تُعرض بواسطة التضمين الرسمي، ولا يضمن RSS إرجاع كل الصور كملفات قابلة للاستيراد.

## مستودع GitHub جديد دون التأثير على موقعك المنشور

1. أنشئ مستودعًا **جديدًا** باسم `omar-maro-portfolio` في حسابك GitHub، بعيدًا عن مستودعات المشاريع الأخرى.
2. ارفع جميع محتويات هذا المجلد إلى جذر المستودع على فرع `main`.
3. افتح **Actions > Sync Omar Maro Behance projects > Run workflow** للاختبار؛ راجع السجل للتأكد من العثور على مشاريع فعلية.
4. لتجربة نسخة موقع مستقلة: فعّل **Settings > Pages > Source: GitHub Actions**؛ المستودع يتضمن Workflow جاهز للنشر.
5. لا تغير أو توجّه نطاق الموقع القديم `chatgpt.site` إلى هذا المشروع حتى توافق على الشكل والنتيجة، لأنه مستقل عن هذا المستودع.

## مشروع يدوي

يمكن إضافة كائن إلى `data/projects.json` (راجع مثال `omar-maro-identity`). الحقول الأساسية: `id`, `title`, `category`, `category_label`, `year`, `cover`, `images`, `description`, `story`, `url`. مصادر الصور يمكن أن تكون من `assets/` أو روابط HTTPS. التصنيفات: `branding`,`social`,`covers`,`print`,`ai`.

## الاستخدام والمسؤولية

- استيراد محتوى الحساب **العام** فقط؛ لا يطلب كلمة سر أو يملك صلاحية تعديل/حذف حساب Behance.
- لا يتم التعامل مع مشاريع خاصة أو غير منشورة ولا تجاوز تسجيل الدخول.
- التحديثات ليست لحظية، وقد تتأخر جدولة GitHub Actions.


## إصلاح مشكلة صور الغلاف المصغّرة / استيراد المشاريع الكاملة

- يعرض الموقع صور المشاريع بترتيبها وبنسبها الأصلية، ويحاول نسخة `source` عالية الجودة ثم `fs` ثم `max_1200` عند تعذر فتحها. الصور غير الموجودة أصلًا لا يمكن تحسينها بمجرد تعديل DPI.
- `scripts/import-project-details.mjs` يقرأ صفحة المشروع العام ويتتبع العناصر التي تتحمل عند التمرير ويستخرج روابط صور `project_modules`، مع التحقق من عينة صغيرة من ملفات CDN.
- بعد كل مزامنة يتم تسجيل تشخيص لكل مشروع في `data/sync-status.json`. إذا تعذر الوصول إلى صفحات Behance، يحتفظ بالأعمال الموجودة ولا يتظاهر بنجاح الاستيراد.
- **حل احتياطي اختياري إذا منع Behance استخراج الصور:** يمكن إضافة سر `SCRAPPA_API_KEY` إلى Settings → Secrets and variables → Actions → New repository secret. يتم استخدامه فقط عندما لا يستطيع المستورد قراءة الصور العامة من Behance. هذه خدمة خارجية قد تكون مدفوعة ويجب مراجعة أسعارها وشروطها قبل إضافتها؛ لا يحتاج السكريبت إلى كلمة مرور Behance.
- لا ترفع ملفات مشاريعك الأصلية أو كلمات المرور إلى مستودع عام.
- GitHub Actions يحدّث البيانات دوريًا؛ راجع آخر تشغيل وحالة `with_images` في ملف التشخيص، وليس نجاح اختبارات الوحدة فقط.

## تحديث نوفمبر 2026 — حل استيراد المشاريع الكاملة

لا يعمل الاستيراد القديم من صفحات Behance العامة من GitHub Actions، بسبب ردود HTTP 403. الصورة المصغرة في `data/projects.json` ليست المشروع الكامل. لذلك أصبح مسار المزامنة النشط هو `scripts/sync-via-provider.mjs` باستخدام خدمة **Scrappa** الخارجية (غير تابعة لـAdobe أو Behance). لا يتم الاتصال بحسابك أو إدارة مشاريعك عليه؛ القراءة فقط للمحتوى العام.

**خطوة تفعيل واحدة من مالك المستودع:**

1. أنشئ حسابًا مجانيًا على https://scrappa.co، واحصل على API key من Dashboard > API Keys. راجع شروط الخدمة والتكلفة قبل التفعيل (المعلن حاليًا 500 credit مجاني شهريًا، وكل طلب مشروع واحد يستهلك credit).
2. افتح `Settings > Secrets and variables > Actions > New repository secret` في GitHub الخاص بمستودع `omar-maro-portfolio`، وسمِّ السر `SCRAPPA_API_KEY`، ثم ضع قيمة المفتاح داخل GitHub فقط. **لا تنسخ المفتاح في المحادثة، ولا تضعه داخل ملفات المشروع.**
3. شغّل `Actions > Sync Omar Maro Behance projects > Run workflow` مرة واحدة. شاهد `data/sync-status.json` بعد التشغيل: يجب أن يكون `with_modules` أكبر من صفر؛ إن كان صفرًا أو فشل المصدر، لا تعتبر الاستيراد ناجحًا.

المستورد يقرأ قائمة المشاريع من الـprofile ثم البيانات التفصيلية لكل مشروع، بما فيها ترتيب الصور والنصوص والفيديوهات المدعومة. ويُحدّث المشاريع الجديدة تلقائيًا في GitHub Pages كل ست ساعات تقريبًا. لتقليل استهلاك الرصيد، يقرأ تفاصيل المشروع الكامل فقط عند إضافته أو إذا لم تكن بياناته كاملة أو عند مرور سبعة أيام من آخر تحقق؛ مع 12 مشروعًا يتوقع أن يظل الاستهلاك العادي ضمن الباقة المجانية المعلنة، لكن السعر والحدود خاضعان لمزود الخدمة.

**حدود مهمة:** المشروع الكامل ما زال غير مستورد حتى يعمل الاختبار بمفتاح صالح بنجاح. أكبر صور CDN المتاحة لا تعني الحصول على الأصل المرفوع أو زيادة DPI. مصدر Scrappa قد يفشل أو يغيّر شكل الاستجابة. كحل مضمون للجودة الأصلية دون الاعتماد على خدمة خارجية، قدّم ملفات الصور الأصلية للمشاريع دفعة واحدة (مجلد ZIP مرتّب حسب المشروع) لإضافتها للموقع.
